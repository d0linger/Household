# Documents workspace contract

All DO01–DO20 are implemented as one module block and remain unaccepted until joint actual tests finish. The [120-step plan](documents-module-plan.md) owns progress; [the 180 criteria](improvements-180.md) own acceptance.

## Data and rights

Documents2 contains twelve schema-local domain tables: released documents plus profiles, file_versions, scan_sets, scan_pages, deadlines, saved_views, rules, processing, integration_sources, import_receipts and command_receipts. Core34 adds eleven safe audit policies (163 total) and composes exact predecessor catalogs without editing any of the 102 released SQL files. Fuel11/Pantry17/Mealplan12 carry narrowly checked forward compatibility. Migration order preserves the complete accepted Core33 predecessor. Documents readiness captures tables, constraints, indexes, triggers, function bodies, owners and ACLs.

Household readers can read documents, originals, safe previews, extracted text and portable archives while Documents is enabled. Editors can review, upload, classify, manage deadlines and links; only administrators approve optional inputs. There is no separate private-document ACL: Finance targets retain their own current policy, and an unavailable link exposes no cached target title or target identity. Saved views are personal. Authorization precedes durable receipt replay. Every mutation verifies a live session, household, enabled module generation and relevant versions. No private response is added to PWA caches or browser persistent storage.

## Originals, scans and processing

PDF/JPEG/PNG originals retain exact uploaded bytes and SHA-256; image previews are separately sanitized. Released image attachments can only be preserved as their previously stored sanitized bytes and are labeled legacy; missing historical camera metadata cannot be reconstructed. No original is overwritten or automatically deleted. Explicit current selection is independent of upload. Limits: 10 MiB per original, 20 million decoded image pixels, 100 versions per document, 100 source PDF pages, 20 selected pages per derived PDF/OCR operation, 80 kB extracted text, bounded tool output and a 48-second worker context under a current 60-second lease. Encrypted/invalid/oversized PDFs produce an actionable failed job rather than partial indexed text. PDF text extraction precedes optional Tesseract OCR; only local executables are used. Metadata remains manual until explicitly reviewed; rules use literal text conditions and exclude manual keys.

Scan preview validates original identities and ordered page numbers. Merge and split create a new derived PDF; current selection remains explicit. Processing checks module generation, lease, cancellation and requester rights before publishing results. Cancellation stops subprocess work through a polled cancellation context; abandoned results are removed. Job retry retains the original source and is explicit. A file quota protects original and derived uploads.

## Optional sources and data ownership

All inputs require operator configuration plus an active administrator's generation-bound approval. Watch folder reads only stable, producer-renamed `*.ready.pdf`, `*.ready.jpg`, `*.ready.jpeg`, `*.ready.png` regular files through os.Root; no symlink traversal outside the root, source move or source deletion. Producer contract: write under a temporary name, fsync/close, atomically rename to the ready name, then leave immutable. Each polling batch is bounded; a durable lexical cursor and source/key/hash receipt avoid duplicate records on retry.

IMAP requires implicit TLS with certificate verification. A bounded read-only EXAMINE plus UID SEARCH and BODY.PEEK fetches attachments without changing Seen flags or deleting messages. Import identity includes UIDVALIDITY, UID and attachment position. MIME depth, parts, message size and decoded attachment batch size are bounded. Credentials never enter UI, exported metadata or logged remote errors. Protocol basis: [IMAP4rev2 RFC9051](https://www.rfc-editor.org/rfc/rfc9051.html).

Paperless requires a fixed HTTPS origin, token and explicit tag ID. Only scoped lists and original downloads are requested; redirects and remote next-link URLs are not followed. Repeated reads deduplicate source/id/hash; changed remote content becomes a separate unreviewed local copy and never overwrites local manual edits. It is a one-way import, with Household owning its copied originals and metadata. It does not claim bidirectional synchronization or preservation of Paperless object ACLs. Basis: [Paperless maintained API documentation](https://github.com/paperless-ngx/paperless-ngx/blob/main/docs/api.md). Local access follows the documented Household household roles; enable only for documents appropriate for those members.

## Export, retention and recovery

Explicit selection of 1–50 documents exports a portable ZIP with manifest.json, ordered original identities, exact hashes, metadata, deadlines, scan provenance and currently authorized links. Cap: 100 files and 64 MiB original bytes; corrupt/missing originals fail before HTTP headers. Internal storage keys, session values and integration credentials are excluded. Archiving preserves all original versions. Full deletion remains a separate Owner-only verified-backup-gated purge; backup archives keep their own documented retention and need the established encrypted retention procedure. Actual nonempty file restore and independent-data-preserving purge are release gates, not inferred from the existence of this document.
