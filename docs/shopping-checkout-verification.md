| Area | Checked implementation and interface evidence |
|---|---|
| Guided review | One position at a time has a progress label and keyboard focus. Purchased goods require an explicit stock destination or a no-stock decision; unavailable and unchecked goods are explicitly skipped. Product and location selection reuse the existing searchable reference controls. The server requires every position exactly once, with a 500-position bound. |
| Exact amounts | Actual purchase quantities are physical amounts or individual pieces, distinct from catalogue packs. Client and server preserve decimal precision and reject incompatible units, rounding, overflow and fractional integer-only stock. The browser fixture stores **1.500007 kg as 1500.007000 g** in one lot. |
| Plan and receipt comparison | The review and saved completion show planned and actual amounts, known prices and unknown counts. Blank price means unknown; explicit zero means free. A ready receipt belonging to the same list and module generation can be selected. The fixture's **€8.50** receipt against **€8.00** in actual item prices leaves **€0.50** explicitly unallocated. Upload remains an earlier separate operation. |
| Conflict recovery | A changed source blocks confirmation. Refresh names the changed article and its old/new planned quantity, while retaining actual purchase input and the selected authorized receipt. A refresh that empties the list closes stale editing and confirmation controls and retains the return link. |
| Durable completion | The store code holds the list and module barriers, uses non-waiting child/target locks, validates selected versions and commits the snapshot, lots, movements, projections, links and list archive in one transaction. The stored request hash permits identical new-key retries to return the existing completion; a different payload is rejected. Current authorization still precedes replay. |
| History | Completion is immutable. It keeps the reviewed plan, purchase decisions and receipt comparison. Later stock corrections belong to the linked lot; current destination links depend on the active Pantry generation. A new purchase starts from a copied list. No automatic finance posting is included. |
