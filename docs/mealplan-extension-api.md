# Mealplan completion API

Source contract for MP08/13/15/19. This document describes implementation; executed acceptance belongs in the module validation record. All private routes require a current session and enabled Mealplan. Mutations require CSRF, exact JSON member names, a UUID `Idempotency-Key`, `generation`, `plan_version` and `week` (`YYYY-MM-DD`, seven calendar dates). Invalid input422, named stale/contention409, missing scope404, denied authority403. Payloads are bounded to1MiB and request execution to20seconds. No external services or automatic stock posting are involved.

| Route below `/api/v1/planning/{plan}` | Contract |
|---|---|
| GET `leftovers?week=…` | Bounded source/allocation projection with current/stale review state, exact production/surplus/allocated portions and reciprocal meal IDs. |
| POST `leftovers` | Closed actions `source_save`, `source_delete`, `allocation_save`, `allocation_review`, `allocation_delete`; current source/component/target/allocation versions according to action. Writers only. |
| GET `budget?week=…` | Versioned settings, known EUR minor subtotal, unknown count, completion, approximate rounding, current/stale provenance and per-meal lines. |
| POST `budget` | `settings_version`, nullable canonical integer-string `budget_minor`, object `manual_estimates` keyed by meal UUID (`meal_version`, `minor`), and all five integer rule weights. Writers only. |
| POST `autoplan/preview` | `recipes_generation`,1–20 candidates (`source_version_id`),1–28 selected empty slots (`planned_on`, `slot`, exact string `servings`, optional selected `source_version_id` or `leave_empty`), and rules. Writers only. |
| POST `autoplan/apply` | Exact reviewed input plus `review_fingerprint` and opaque `review_proof`; one explicit atomic save of selected proposals. Writers only. |
| GET `calendar.ics?week=…` | Authenticated all-day ICS attachment containing title/slot/status only, plus minimal cancellations. Readers permitted. |
| GET `calendar-feeds?week=…` | Current issuer's personal feed metadata, including for administrators, no secret/hash. All active/nonexpired feeds first, then newest revoked/expired rows;100-row limit with explicit `more` for older history. The20-active issuer cap keeps every live personal link reachable for revocation. |
| POST `calendar-feeds` | `action=create`. Explicit personal seven-day sharing, including Readers. At most20 active capabilities per issuer, fixed90-day expiry. |
| POST `calendar-feeds/{feed}/revoke` | `action=revoke`, exact feed `version`. Issuer or current administrator only. |

Rules are the closed members `stock`, `urgency`, `effort`, `cost`, `repetition`, each0–100. A missing price or effort gets no free/zero advantage. Prices more than90calendar days old remain visible as stale prior estimates; they are excluded from a current complete budget claim. Recipe costs use the plan's immutable snapshot and production portions, never a changed live recipe. Reviewed manual zero is valid; absence is unknown. A currently reviewed complete leftover allocation adds no duplicate production cost.

Leftover source review uses `meal_id`, `meal_version`, `component_id`, `component_version`, `expected_servings`, and optional existing `source_id`/`source_version`. Allocation review uses current source identity/version, `target_meal_id`, `target_version`, `servings`, and optional `allocation_id`/`allocation_version`. Deletions require existing row/version. Expected surplus is carved out of production; stale allocations retain capacity until explicit reconciliation. Generic moves/edits/deletions and copies retain the same invariants. Crossing a selected copy-window boundary requires explicit link review before copying.

Autoplan returns explained candidate/slot contributions and alternatives, shared simulated stock notes, bounds, `review_fingerprint`, `review_proof` and Unix `review_expires_at`. Change any input and obtain a fresh preview. The five-minute signature binds household/user/membership/session/role/auth version/plan, complete input and dependency fingerprint. Apply rechecks sources/settings/current stock/price authority under locks. A matching committed replay can return the original result even after preview expiry; an expired uncommitted command cannot create meals. No reservations, stock movements, purchases or real leftovers are created by preview/apply.

Public feed retrieval is `GET /calendar/mealplan/{opaque-token}.ics`, with no query parameters. The wildcard internally includes the suffix because Go HTTP wildcards occupy full path segments. Every fetch rechecks active issuer/membership, captured authority, password-change state, module/generation, plan, expiry and revocation before responding. PostgreSQL-backed per-IP retrieval limiting survives restarts. Conditional requests do not bypass authorization. Browser logout does not revoke a separate personal sharing capability; explicit revoke or issuer/account authority changes do.

Creation returns feed metadata plus a relative `url` **once**. Only its SHA-256 hash is stored. The committed idempotency receipt contains metadata only; a matching creation retry returns `secret_unavailable=true` and cannot redisplay the URL. If the first response is lost, inspect/revoke that feed and explicitly create another. No token belongs in local storage, IndexedDB, cache, logs, error rendering, export bundles or copied-week settings. The UI clears its one-time DOM display on close/week change/page exit. All calendar responses are private/no-store/no-referrer and bypass service-worker fetch handling.

Calendar events use stable household/generation/meal UIDs, monotone source versions, UTC modification stamps, DATE start and exclusive next-day end, RFC5545 escaping and UTF-8-safe75-octet folding. Slot names are labels, not invented clock times. Up to42 current meals and512 minimal cancellation identities are supported per feed window; overflow fails explicitly. Moved-out/deleted events contain no deleted title. Vendor-specific subscribed-calendar refresh/display behavior is a separate interoperability check; it is not inferred from serializer or browser tests.
