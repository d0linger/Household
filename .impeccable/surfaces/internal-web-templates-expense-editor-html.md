# Shared expense editor

Mode: Operate. EX02 extends the existing Expenses module under the approved all-180 instruction. The task, exact allocation rest, draft/post distinction and inherited visual identity are settled in PRODUCT.md, DESIGN.md and docs/finance-workspace.md. This is a code-led local extension, with no new visual world, raster asset or concept tournament.

## Direction contract

THESIS: edit one shared household entry and its category lines together, with a visible exact remainder and an explicit final posting decision.

OWN-WORLD: preserve Household's existing sage/forest palette, local system typography, labelled native controls, restrained panels and 44px actions. Keep the module navigation and light/dark/system modes. No new fonts, libraries or illustrations.

STORY: open or create a draft; enter exact EUR and a known or explicitly unknown payer; add, reorder or explicitly remove category lines; see the live remainder; save an incomplete draft or review an exactly allocated posting. Posted records stay readable and immutable. Household sharing remains explicit; selected visibility is unavailable.

FIRST VIEWPORT: breadcrumb/back action and title, saved/draft status and household-sharing sentence, then a bounded form with description, date, payee, amount/direction and payer. Allocation rows follow with a persistent in-flow total/remainder and distinct Save draft/Review posting actions. Mobile rows stack labels and controls without horizontal scrolling; desktop uses the existing form grid.

FORM: inherited code-led module extension; no seed is needed for this precisely specified scope. Searchable paged category/payer selection preserves historical inactive labels. Errors retain inputs; conflicts compare against fresh state before explicit reload. Unknown outcomes retain the exact pending body/key for retry and lock editing until resolved. Financial edits are never added to the generic device queue. Existing queued financial drafts require an explicit recovery/discard path, without silent deletion. No automatic save, posting or local financial form persistence.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance. Capture desktop/mobile light/dark, draft/rest, posting review, reader/posted, validation, conflict and uncertain-result states in one inspection batch; correct material findings together and confirm once. Obtain a fresh no-history finish reviewer and a separate documenter. Preserve DESIGN.md and absent sidecar; report inherited drift without repairing it.
